# The rules of a good ask

## Every prompt
1. Lead with the job in one sentence.
2. Say what done looks like: the format, the depth, what you'll do with it.
3. Name the environment or situation: system, version, limits, people involved.
4. Pick one: one answer, a few options, plan first, or just do it.
5. Give an example of what you want when you have one.

## Code and scripts
1. OS, language and version, and whether you have admin rights.
2. Paste the exact error text, not "it broke."
3. Paste the current script instead of describing it.
4. Ask for the complete script plus what each part does.
5. Say where it runs and how often: once, scheduled, on a server.

## Work and NetSuite
1. Say what access you have: admin, no SuiteScript, limited SuiteQL.
2. Name the audience: you, a manager, a vendor.
3. Ask for click-by-click steps when it lives in a UI.
4. For emails, give the goal and the relationship, then ask for 2 versions.
5. Keep work in the work project so context stays separate.

## Life and decisions
1. Lay out the real options, including "do nothing."
2. Say what matters most: time, money, family, health.
3. Ask Claude to push back, not just agree.
4. Ask for the tradeoffs and a recommendation, both.
5. End with "what's the first small step this week?"

## Starting a project
1. Describe the idea and why you want it.
2. State your limits: weekends only, budget, skill level.
3. Ask for phases, with phase 1 doable in one sitting.
4. Ask for the plan first, then build one phase at a time.
5. Put the project in its own Claude project so it remembers.

## When it misses
1. Say exactly what's off: too long, wrong tool, ignored X.
2. Quote the part that's wrong.
3. Correct it in the same chat; start fresh only if the chat got tangled.
4. After 3 misses, restart with a full ticket from the builder.
5. If a correction should stick, say "remember this."
