# Start a project

**Use:** Kicking off a new build: an app, a homelab service, a home or business project.

```
Project: [What you want to exist when it's finished]

Why: [The real reason you want it]

Limits: [Time, budget, tools, skill level]

Done looks like: A phased plan where phase 1 works in one sitting, with exact files and commands for phase 1.

How to answer: Show me the plan first and wait for my go-ahead before doing anything. Be thorough; detail is fine.
```

## Before you start: the 3-question filter

1. Who benefits, and would they notice?
2. Can I show the result in a number (hours, dollars, errors)?
3. Will I still use it in 3 months?

Two no's means skip it, or treat it as a weekend toy.

## Example

```
Project: A self-hosted dashboard that shows all my homelab services and whether they're up.

Why: I keep forgetting what's running where, and I want one page to check every morning.

Limits: Weekends only, $0 budget, Docker on my existing server. I'm comfortable editing configs, not writing apps.

Done looks like: A phased plan where phase 1 works in one weekend, with the exact files and commands for phase 1.

How to answer: Show me the plan first and wait for my go-ahead before doing anything. Be thorough; detail is fine.
```
